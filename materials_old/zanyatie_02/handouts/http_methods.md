# HTTP-методы: справочник
## Занятие 2: Маршрутизация и обработка запросов

---

## GET - Получение данных

**Использование:** Чтение ресурсов без изменения данных

**Примеры:**
```
GET /api/users/           - получить всех пользователей
GET /api/users/123        - получить пользователя с ID 123
GET /api/posts?sort=date  - получить посты с сортировкой
```

**Характеристики:**
- Idempotent (повторный вызов не меняет состояние)
- Кэшируется браузером
- Данные передаются в URL (query parameters)

---

## POST - Создание ресурса

**Использование:** Создание новых данных на сервере

**Примеры:**
```
POST /api/users/          - создать нового пользователя
POST /api/posts/          - создать новый пост
POST /api/auth/login      - авторизация
```

**Характеристики:**
- Не idempotent (повторный вызов создает дубликаты)
- Данные передаются в теле запроса (body)
- Обычно возвращает 201 Created

**Тело запроса (JSON):**
```json
{
  "name": "John Doe",
  "email": "john@example.com"
}
```

---

## PUT - Полное обновление

**Использование:** Полная замена ресурса

**Примеры:**
```
PUT /api/users/123       - полностью заменить пользователя 123
```

**Характеристики:**
- Idempotent
- Требует все поля ресурса
- Отсутствующие поля = null/default

**Тело запроса:**
```json
{
  "id": 123,
  "name": "John Smith",
  "email": "john.smith@example.com",
  "age": 31
}
```

---

## PATCH - Частичное обновление

**Использование:** Изменение части ресурса

**Примеры:**
```
PATCH /api/users/123      - изменить только email пользователя
```

**Характеристики:**
- Не idempotent
- Только изменяемые поля
- Более гибкий чем PUT

**Тело запроса:**
```json
{
  "email": "newemail@example.com"
}
```

---

## DELETE - Удаление

**Использование:** Удаление ресурса

**Примеры:**
```
DELETE /api/users/123     - удалить пользователя 123
```

**Характеристики:**
- Idempotent
- Обычно возвращает 204 No Content
- Может возвращать 200 с удаленным объектом

---

## HEAD - Заголовки

**Использование:** Получение только заголовков ответа

**Примеры:**
```
HEAD /api/users/123       - проверить существование пользователя
```

**Характеристики:**
- Idempotent
- Тело ответа отсутствует
- Используется для проверки существования

---

## OPTIONS - Доступные методы

**Использование:** Узнать какие методы поддерживает ресурс

**Примеры:**
```
OPTIONS /api/users/       - получить разрешенные методы
```

**Характеристики:**
- Idempotent
- Используется для CORS preflight
- Возвращает заголовок `Allow`

**Ответ:**
```
Allow: GET, POST, PUT, DELETE, OPTIONS
```

## Best Practices

1. **Используйте правильные методы:**
   - GET для чтения
   - POST для создания
   - PUT/PATCH для обновления
   - DELETE для удаления

2. **Именование ресурсов:**
   - Используйте существительные во множественном числе
   - `/users/`, `/posts/`, `/comments/`

3. **Вложенные ресурсы:**
   - `/users/123/posts/` - посты пользователя 123
   - `/posts/456/comments/` - комментарии поста 456

4. **Query parameters:**
   - Фильтрация: `?age_gt=18`
   - Сортировка: `?sort=name`
   - Пагинация: `?page=1&limit=10`
   - Поиск: `?search=john`
